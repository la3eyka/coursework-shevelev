# Поэтапный план курсовой работы

Тема: **«Исследование методов оптимизации загрузки веб-страниц: разработка инструмента анализа и рекомендаций»**.

| Неделя | Этап | Результат, который можно проверить |
| --- | --- | --- |
| 01 | Архитектура, структура и базовый запуск | Fastify `GET /api/health`, React с реальным запросом к API, README, тест |
| 02 | Интеграция Lighthouse | Запуск Chrome/Lighthouse и получение JSON по одному допустимому URL |
| 03 | Обработка метрик | Получение Performance Score, FCP, LCP, TBT, CLS; обработка ошибок; REST API |
| 04 | Рекомендации | Собственные правила по аудитам и приоритетам, тесты правил |
| 05 | Хранение данных | Docker Compose, PostgreSQL, Prisma, история анализов |
| 06 | Полный интерфейс | Форма URL, результаты, графики и сравнение запусков |
| 07 | Эксперимент | Тестовый сайт до/после, не менее 5 запусков каждого варианта, таблица и графики |
| 08 | Финализация | Проверки, устранение ошибок, выводы, итоговая документация и демонстрация |

## Принципы выполнения

- Каждый этап развивает **один репозиторий**, а не создаёт отдельный несвязанный проект.
- По каждому этапу формируется `docs/weekly/NN.md` с перечнем изменений, командами проверки и наблюдаемыми результатами.
- Только действительно работающий функционал указывается как реализованный.
- После сдачи этапа обновляется указатель Git-сабмодуля в репозитории преподавателя отдельным Pull Request.
- В итоговом исследовании условия замеров и версии инструментов фиксируются, а выводы строятся по реальным данным.
